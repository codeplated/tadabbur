# Tadabbur — Quartz Site

> Bismillah. This repo publishes the Tadabbur knowledge base as a website.

---

## What This Repo Does

Takes the markdown vault generated by the Tadabbur generator repo and
builds a fully navigable website using Quartz 5. It is deployed to
Cloudflare Pages at `tadabbur.belambo.com` — see Deployment below.

## PROTECTED — Do Not Touch Without Strong Reason

### `/content` folder — GENERATED CONTENT

Every file inside `/content` is generated by the Tadabbur generator repo
and synced here. **Do not manually edit any file inside `/content`.**

- Edits will be overwritten the next time the generator runs
- If content is wrong, fix it in the generator repo, not here
- Don't work around generator output with Quartz-side remaps either —
  change the generator
- The front page (slug `index`) hides its title, date, breadcrumbs and
  properties box via the `condition: not-index` layout condition in
  `quartz.config.yaml`, so it needs no frontmatter.

What this site expects from the generator:

| Field / file                                                                                             | Used by                                          |
| -------------------------------------------------------------------------------------------------------- | ------------------------------------------------ |
| `surah`, `ayah` (`"2 / 286"` style), `surah_name` (`"English / Arabic / Urdu"`)                          | tag-page patch (grouping, ordering, labels)      |
| `index.md` in a folder — surah folders, `0 - Explore`, and its two subfolders                            | folder-page (it replaces the stock file listing) |
| An `English` heading followed by the translation line                                                    | tag-page patch (ayah text on tag pages)          |
| `image: "/attachments/surah_NNN.png"` on surah `index.md` notes                                          | `Quran.base` card images                         |
| `tags`                                                                                                   | tag-list, tag pages                              |
| `0 - Explore/Quran.base` — one `cards` view of the surah `index` notes, sorted by `formula.surah_number` | bases-page                                       |
| `*.canvas` (JSON Canvas) — rendered as interactive pages, e.g. `The Opener.canvas`                       | canvas-page                                      |

All other frontmatter fields are shown as-is in the properties box.

### `quartz.ts` — entry point

Do not edit this file. It is a thin loader that calls Quartz internals.

### `node_modules/` — dependencies

Never edit, never commit. Managed by npm.

**Never hand-edit files inside `node_modules/` to fix a plugin bug**, even
temporarily "just to test something." It's gitignored, so the fix vanishes
on the next `npm install` and silently regresses on deploy with no diff to
explain why. If a community plugin needs a behavior change:

1. Edit the file under `node_modules/` to find the right fix.
2. Run `npx patch-package <package-name>` — this diffs your edit against a
   clean copy and writes a `.patch` file into `patches/`.
3. **Pin that package to an exact version in `package.json`** (`"0.1.0"`,
   not `"^0.1.0"`). A patch only applies to the version it was made from.
4. Commit the `patches/` file and `package.json` / `package-lock.json`.

`npm install` / `npm ci` re-apply every patch via the `postinstall` script
(`patch-package`) and fail loudly if one no longer applies. Verify with
`npm ci` and look for a tick next to each patch.

Community plugins ship their components twice: `dist/index.js` and
`dist/components/index.js`. The build loads layout components from
`dist/components/index.js`, so a patch must change **both** files or the
change silently doesn't show up.

To upgrade a patched plugin: bump the exact version, run `npm install`,
fix whatever part of the patch fails, and regenerate it with patch-package.

Why patches and not forks: a local or git-sourced plugin gets symlinked or
cloned into `.quartz/plugins` and built with its own toolchain on every
deploy. Patches keep the stock npm package and only store the diff.

Existing patches:

- `@quartz-community+graph+0.1.0.patch` — three fixes in the graph's inline
  script: (1) decodes `window.location.pathname` so the current page is
  found when the slug contains Arabic (otherwise the local graph can't
  highlight the page you're on); (2) skips `.base` files when building the
  node set, so `Quran.base` isn't a graph hub. It matches on the `.base`
  extension, so it covers any base file the generator emits; (3) returns
  before loading d3 and pixi.js when `(hover: none)` matches, so touch
  devices don't pull ~700KB off a CDN and force-simulate 6,500 nodes for a
  box no finger can usefully pan. `custom.scss` hides the empty frame under
  the same query, so the two always agree — including when a tablet is
  rotated.
- `@quartz-community+explorer+0.1.0.patch` — the file tree scrolls its active
  item into view on load with `scrollIntoView`, which scrolls every scrollable
  ancestor, the document included. With 114 surah folders that opened each page
  285px down on a tablet and 341px down on desktop, below the title. The patch
  scrolls the tree's own container instead. (Phones were unaffected: their tree
  is a fixed drawer, so there was nothing for the document to scroll.)
- `@quartz-community+folder-page+0.1.0.patch` — the plugin always appends a
  raw file list under a folder's own page. Every surah folder now has an
  `index.md` that lists its ayaat in order, so the appended list repeated all
  286 of them sorted as text (2_1, 2_10, 2_100 …) and undid the point of the
  index. The patch skips the list when the folder note has content of its own;
  a folder without an index still gets the stock listing.
- `@quartz-community+tag-page+0.1.0.patch` — replaces the stock date-sorted
  title list on tag pages. A tag page groups ayahs by surah in Quran order
  (from `surah`, `ayah`, `surah_name`), shows each as `surah:ayah` with its
  English translation and other tags, adds a surah jump bar, and lists
  non-ayah pages (personalities, names) under "Related pages", after the
  ayaat — they used to come first, which on a phone put a couple of thousand
  pixels of secondary content ahead of the verses the tag is about. The
  translation is the first line after the `English` heading, or frontmatter
  `description` if the generator sets one. `/tags` becomes an A–Z grid of
  tags with page counts. An intro for a tag comes from
  `content/tags/<tag>.md` if the generator writes one.
- `@quartz-community+footer+0.1.1.patch` — the "Created with Quartz vX" line
  is hardcoded in the plugin, so the patch replaces it with "Created with a heart
  by Belambo" (links to https://belambo.com). The `footer` option links sit
  on the same row, open in a new tab, and a link named `GitHub` renders as
  the GitHub icon instead of text.

These files differ from upstream Quartz. Re-check them after pulling a
Quartz update:

| File                                                                | Change                                                                                                                                                                                                                                                                                                           |
| ------------------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `quartz/plugins/emitters/static.ts`                                 | Files under `quartz/static/root/` are copied to the site root instead of `/static/` (`robots.txt`; a Pages `_headers` file would go there too)                                                                                                                                                                   |
| `quartz/plugins/transformers/scriptLang.ts`                         | New transformer: tags Arabic-script text `lang="ar"` or `lang="ur"` so CSS picks the right font and direction                                                                                                                                                                                                    |
| `quartz/plugins/transformers/index.ts`                              | Exports `ScriptLang`                                                                                                                                                                                                                                                                                             |
| `quartz/plugins/loader/config-loader.ts`                            | Registers `ScriptLang` as a built-in transformer                                                                                                                                                                                                                                                                 |
| `quartz/components/Head.tsx`                                        | Loads Scheherazade New, Noto Naskh Arabic, Noto Nastaliq Urdu and Noto Emoji from Google Fonts                                                                                                                                                                                                                   |
| `quartz/components/scripts/popover.inline.ts`                       | `setupPopovers` returns early when `(hover: none)` matches. A tap fires `mouseenter`, so on a phone every link touched fetched and parsed the whole target page for a card that flashed up and was navigated away from                                                                                           |
| `quartz/styles/custom.scss`                                         | All site styling, including the CSS-mask logo and the phone/tablet layout. Its "Interaction colour" section makes every hover, focus, pressed and selected state use `--tertiary` (`#607300`, the same in both themes, by choice) — plugins' own hover colours included, so new plugin UI needs a rule there too |
| `quartz/components/Feedback.tsx`, `quartz/static/feedback.{css,js}` | Floating feedback form. | `quartz/components/HomeHero.tsx`, `quartz/static/keffiyeh.svg`      | Front page hero: the "A structured Quran Knowledge Base" heading over a band of keffiyeh pattern. Renders on slug `index` only. The SVG is `assets-src/Keffiyeh.svg` through `svgo --precision 2`, used as a CSS mask so the theme colours it                                                                    |
| `quartz/components/index.ts`                                        | Exports `Feedback` and `HomeHero`                                                                                                                                                                                                                                                                                |
| `quartz/plugins/loader/config-loader.ts`                            | `loadQuartzLayout` puts `HomeHero` first in `beforeBody` and appends `Feedback` to `afterBody` on every page type except `404`. They're core components, not plugins, so the yaml layout can't place them                                                                                                        |
| `quartz/static/icon.png`, `logo.svg`, `og-image.png`                | Tadabbur branding (og-image is the default social preview card)                                                                                                                                                                                                                                                  |

The generator writes no emoji. For anything a reader types into a note, the
font stacks end with **Noto Emoji** — the monochrome cut, which holds no Latin
or Arabic glyphs, so it only catches what the text fonts lack and renders an
emoji as a glyph in the surrounding text colour rather than the system's colour
artwork. Keep it last in every stack: moving it earlier would let it claim
arrows and symbols the text fonts should own.

## Plugins

Only plugins the site actually uses are in `quartz.config.yaml` and
`package.json`. Every enabled plugin must be a dependency in `package.json`
— the build does not install npm plugins, so anything only present locally
breaks on deploy.

Plugins that were removed, and why — don't re-add without discussion:

| Plugin                                                                                                                                                                 | Reason removed                                                                                                             |
| ---------------------------------------------------------------------------------------------------------------------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------- |
| `og-image`                                                                                                                                                             | Generated a sharp image for all 6,500+ pages — 10+ min builds. `quartz/static/og-image.png` is used for every page instead |
| `favicon`                                                                                                                                                              | Needs the native `sharp` package just to copy `icon.png`; `Head.tsx` already links `static/icon.png`                       |
| `created-modified-date`                                                                                                                                                | The generator writes no dates, so it fell back to file times — on a deploy that's the checkout time for every page         |
| `alias-redirects`                                                                                                                                                      | No note uses `aliases`                                                                                                     |
| `cname`                                                                                                                                                                | Writes a GitHub Pages `CNAME` file; Cloudflare Pages sets the domain in its dashboard                                      |
| `syntax-highlighting`                                                                                                                                                  | No code blocks in the vault                                                                                                |
| `remove-draft`                                                                                                                                                         | The generator never writes `draft`                                                                                         |
| `latex`, `encrypted-pages`, `stacked-pages`, `comments`, `recent-notes`, `citations`, `hard-line-breaks`, `ox-hugo`, `roam`, `explicit-publish`, `@quartz-themes/core` | Not used by this vault                                                                                                     |
| Plausible analytics                                                                                                                                                    | Not set up (`analytics: null`)                                                                                             |

**Especially: never re-enable `og-image`** without understanding the build
time consequences.

## Deployment — Cloudflare Pages

The build is verified to work from a clean `npm ci` without `.quartz/` or
`public/`, which is what Cloudflare has.

```
Repository:         github.com/codeplated/tadabbur, branch main
Build command:      npx quartz build -d content
Build output dir:   public
Node version:       22   (from .node-version)
Custom domain:      tadabbur.belambo.com
```

Every push to `main` triggers a build (500 a month on the free plan), so sync
generator output in one commit rather than many.

**DNS is at IONOS, not Cloudflare** (`belambo.com`'s nameservers are
`ui-dns.*`). The custom domain is added in the Pages dashboard, and IONOS holds
a `CNAME tadabbur → <project>.pages.dev` record. The same reason rules out
Worker routes on the domain and Cloudflare Email Routing.

Analytics is Cloudflare Web Analytics, enabled in the Pages dashboard — no
code, which is why `analytics: null` stays.

### Feedback Worker

`feedback-worker/` is deployed separately with wrangler, at
`https://tadabbur-feedback.tadabbur-feedback.workers.dev` (Worker name, then the
account's workers.dev subdomain). It forwards each message to Telegram; the bot
token and chat ID are wrangler secrets and must never be committed — the repo
is public. Setup and checks are in `feedback-worker/README.md`.

Everything runs on free plans. Keep it that way: don't upgrade Workers to
Paid, and don't add D1, KV, R2 or other bindings to the Worker without
discussion.

## Configuration — `quartz.config.yaml`

```yaml
configuration:
  baseUrl: tadabbur.belambo.com # never change without updating DNS too
  analytics: null
  ignorePatterns:
    - "**/attachments/audio/**" # audio is served from the CDN instead

plugins:
  note-properties:
    includeAll:
      true # every generator field; hides tags, image
      # (a card thumbnail path, not something a
      # reader needs above the verse) and
      # title/modified/socialImage (added by the plugin)
  obsidian-flavored-markdown:
    enableInHtmlEmbed: true # required — notes contain <audio> HTML tags
  crawl-links:
    markdownLinkResolution: shortest # matches Obsidian wikilink format
  explorer:
    mapFn: … # strips harakat from sidebar names only
```

The explorer `mapFn` runs in the browser and strips harakat (and ٱ → ا) from
every sidebar name. It doesn't depend on folder names; harakat only occur in
`0 - Explore` names today, and page content keeps them.

## Mobile and Tablet

Most readers open this site on a phone, so the small-screen layout is the one
that has to be right. It all lives in the "Phones and tablets" section at the
end of `quartz/styles/custom.scss`.

Two kinds of media query are used there and they are **not** interchangeable:

| Query                     | Means                                | Used for                                                       |
| ------------------------- | ------------------------------------ | -------------------------------------------------------------- |
| `($mobile)` / `($tablet)` | how much room there is               | layout: the app bar, grid columns, card columns, drawer        |
| `(hover: none)`           | the reader is pointing with a finger | tap-target sizes, and anything that used to depend on hovering |

A touch tablet in landscape is wide enough for the desktop layout but still
needs finger-sized controls, which is why the two are kept apart. `--tap-target`
(2.75rem) is the minimum for anything a finger has to hit; `--mobile-bar-height`
(3.5rem) is the app bar, and the explorer drawer and every scroll anchor
measure from it — change one and the other follows.

What the section does, and why, so it doesn't get undone by accident:

- **The app bar.** On mobile the left sidebar becomes a sticky row at the top
  of the page. Stacking the logo above a 1.75rem title made it 179px tall —
  a fifth of an iPhone screen, permanently, with the article scrolling
  underneath it. It is now one 56px row: menu, logo beside the title, search,
  theme. `scroll-padding-top` is tied to its height so heading links and the
  tag-page jump bar don't land underneath it.
- **The explorer drawer** is anchored below the bar rather than over it (the
  menu button used to overlap its first rows), is `position: fixed` rather
  than absolute at `100vw`, and locks the page behind it. Tree rows are
  `--tap-target` tall on touch, in the drawer and the tablet sidebar alike.
- **The graph is skipped on touch** (see Graph View).
- **The right rail stacks** on a phone instead of splitting a 390px screen
  between two widgets, and the backlink list no longer scrolls inside the
  scrolling page.
- **Full-screen UI uses `dvh`, never `vh`** — `100vh` counts browser chrome
  that scrolls away.
- **Search opens at the top of the screen** on mobile; at `12vh` the field and
  most of its results sat behind the keyboard.
- **Cards go two-up** on a phone and three-up on a tablet. One per row turned
  the 114 surahs of `Quran.base` into a 48,000px scroll.
- **A tag page's jump bar** becomes one swipeable row. Wrapped, a busy tag's
  75 surah chips were 20 rows of them before the first ayah.
- **A surah's ayah index becomes a grid of chips on touch.** The generator
  writes the ayaat as a run of numbers separated by "·", which is around 12px
  of tap target each, and it is the way into every ayah of the surah.

Two of these key off headings the generator writes (`## Ayaat`,
`## Connections`, `## Recitation`), in the same way the Arabic verse styling
already keys off `## Arabic`. If those headings change, the styling stops
applying and the page degrades to plain prose — it doesn't break.

Check any layout change at 390px (phone), 768px and 820px (tablet, portrait —
note 768 gets the _mobile_ layout and 820 the tablet one) and 1180px (tablet,
landscape).

## Graph View

The graph renders all 6,500+ nodes using D3 force simulation.
It is known to be slow on initial load.

If improving graph performance:

- Limit initial render depth to 1 (current node + direct connections)
- Cap maximum rendered nodes at ~200
- Reduce D3 simulation alphaDecay and velocityDecay
- Do NOT increase node count or disable depth limiting
- Test on mobile after any change — mobile is the primary bottleneck

`.base` files are excluded from the graph via the graph patch (see above),
and the same patch skips the graph entirely on touch devices — so the
numbers above only ever apply to a desktop browser with a pointer.

## What NOT to Do

- Do not edit any file inside `/content/` — it is generated content
- Do not re-enable `og-image` — it breaks build times
- Do not enable a plugin that isn't in `package.json`, or one that needs a
  native package (e.g. `sharp`) without adding that too
- Do not use `^` ranges for patched plugins, or add Dependabot/Renovate
  bumps for them — a version change breaks the patch and the deploy
- Do not commit `node_modules/`
- Do not add audio files to this repo — use cdn.islamic.app
- Do not change `baseUrl` without also updating DNS and Cloudflare settings
- Do not edit `quartz.ts`
- Do not add a `prebuild` npm hook
- Do not use `100vh` for full-screen mobile UI — use `100dvh`
- Do not add chrome above the article on mobile without checking what it
  costs above the fold; the app bar and page header are already most of a
  phone screen before the first line of the verse
